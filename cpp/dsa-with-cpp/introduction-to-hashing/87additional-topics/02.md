## C++ unordered_map as Hash Tables

In C++, std::unordered_map is implemented as a hash table, which is why it has an average O(1) time complexity for lookup, insertion, and deletion.

To understand how C++ unordered_map work as hash tables, let's delve into some of the fundamentals:

1. Hash Function

In C++, std::unordered_map uses the std::hash function provided by the STL.

2. Collisions

std::unordered_map handles collisions using chaining.

3. Dynamic Resizing

As more items are added to an std::unordered_map, the underlying hash table might become densely populated, leading to more collisions.

To handle this, std::unordered_map is designed to resize dynamically.

4. Key Invariance

It's important to note that std::unordered_map keys should be immutable.

This is because if a key changes its value (and thus its hash) after it's been added to the std::unordered_map, it would make the value associated with it unreachable.

Let's look at a simple example of using the std::unordered_map.

```cpp
1#include <iostream>
2#include <unordered_map>
3#include <string>
4
5using namespace std;
6
7int main() {
8    // Create an unordered_map
9    unordered_map<string, string> person = {
10        {"name", "John"},
11        {"age", "30"},
12        {"city", "New York"}
13    };
14
15    // Access a value using a key
16    cout << person["name"] << '\n';
17
18    // Insert a new key-value pair
19    person["job"] = "Engineer";
20
21    // Remove a key-value pair
22    person.erase("age");
23
24    // Display the unordered_map
25    for (const auto& kv : person) {
26        cout << kv.first << ": " << kv.second << '\n';
27    }
28
29    // Check if a key is in the unordered_map
30    if (person.find("city") != person.end()) {
31        cout << "City is: " << person["city"] << '\n';
32    }
33
34    return 0;
35}
```

Output

```text
John
job: Engineer
city: New York
name: John
City is: New York
```
