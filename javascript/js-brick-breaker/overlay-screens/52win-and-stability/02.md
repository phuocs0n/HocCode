## Speed Clamping ⚡

The game is nearly complete. There is one small thing that can go wrong over a long session.

Each paddle bounce recalculates the ball's velocity from scratch using trigonometry. In theory the speed should stay constant. In practice, floating point arithmetic accumulates tiny errors across many bounces and the speed can drift upward without you noticing.

The fix is simple. After each frame, check if the ball is moving faster than it should be. If it is, scale it back down.

```javascriptDOM
clampSpeed() {
  const s = Math.hypot(this.ballSpeedX, this.ballSpeedY);

  if (s > BALL_MAX_SPEED) {
    const k = BALL_MAX_SPEED / s;

    this.ballSpeedX *= k;
    this.ballSpeedY *= k;
  }
}
```

Math.hypot gives you the true speed magnitude. Multiplying both components by k scales the velocity down while keeping the direction exactly the same. The ball slows down but does not change course.

Without this, a ball moving too fast can tunnel through walls or bricks entirely, passing through them in a single frame before the collision check runs.

Next, you will add this to the Ball class and the game will be complete.
