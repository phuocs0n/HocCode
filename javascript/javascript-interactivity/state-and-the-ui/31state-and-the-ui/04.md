## Updating the Page from State

Did you notice the order of steps in the counter example?

We updated the variable first. Then we updated the UI.

That order matters more than it might seem.

The variable count holds the current state. Every time the button is clicked, we change that value. Then we update the text on the page using display.textContent = count.

The UI does not decide what the value is. The variable decides. The UI reflects it.

This pattern keeps your logic predictable:

- Update the state
- Update the UI

If you try to read from the DOM to decide what to do next, things can easily get out of sync. One variable as the source of truth keeps your code clean and easy to follow.
