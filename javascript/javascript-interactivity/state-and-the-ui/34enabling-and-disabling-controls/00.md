## Boundaries: When to Disable Buttons

The slider moves. The buttons respond. But right now nothing stops the user from clicking Prev on the first slide or Next on the last.

That is an invalid state. And it needs to be handled.

- On the first slide, Prev should be disabled. There is nowhere to go back.
- On the last slide, Next should be disabled. There is nowhere to go forward.

This prevents an invalid state and gives clear feedback.

Use the current index (for example, currentSlideIndex) to decide:

- If the index is 0, disable Prev
- If the index is the last slide, disable Next
- Otherwise, enable both buttons

You can update the buttons in two ways:

- Set button.disabled = true or false in JavaScript
- Or toggle a class and style the disabled state in CSS

Update this every time the slide changes, so the buttons always match the current position.

Developer Insight

Update the disabled state inside showSlide(). That way, every change goes through one function, and the buttons never fall out of sync.
