## Responding to Scroll

The pattern has not changed. Only the event has.

Instead of listening for a click, this time you are listening for a scroll. The browser fires a scroll event every time the user moves the page.

You listen for it the same way:

```javascriptDOM
window.addEventListener('scroll', handler);
```

To decide when to change the UI, you need to know how far the user has scrolled. That is what a window.scrollY tells you how many pixels the page has moved from the top.

Usually, you compare it to a threshold.

For example, only add a class when scrollY > 100. Remove the class when it's below that value.

So the logic is simple:

- Read the scroll position
- Compare it to a number
- Add or remove a class

Sound familiar? It should.

This follows the same pattern:

Event → Check state → Toggle class.
