# Composition over Inheritance

#### Course: Modern JavaScript Essentials

## Composition over Inheritance

Inheritance gets a lot of attention, but in practice, composition is the more flexible pattern. Instead of making classes inherit from each other, you create small, focused classes and combine them. Each class does one thing, and a larger class holds the others as properties.

For example, a TaskBoard class does not inherit from Task or User. Instead, it creates a Task and a User and coordinates them. This is composition - the board "has a" task and "has a" user.

```javascript
class Task extends TaskBoard { ... }

// Composition: "has a" (loose coupling)
class TaskBoard {
    constructor() {
        this.task = new Task();
        this.user = new User();
    }
}
```

I default to composition over inheritance in every project I work on. With inheritance, changing one class can break others that depend on it. Composition keeps each piece independent.

I always ask "does this have a [thing]?" before "is this a [thing]?". This keeps things simpler.
