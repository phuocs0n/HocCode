## Composing with Classes

Let's see the full pattern. Each class stays small and focused, and the Game class combines them using everything you have learned - classes, constructors, template literals, and object properties.

For example,

```javascript
1class User {
2    constructor(name, role) {
3        this.name = name;
4        this.role = role;
5    }
6
7    describe() {
8        return `${this.name} (${this.role})`;
9    }
10}
11
12class Task {
13    constructor(title, priority) {
14        this.title = title;
15        this.priority = priority;
16    }
17
18    describe() {
19        return `${this.title} [${this.priority}]`;
20    }
21}
22
23class TaskBoard {
24    constructor() {
25        this.task = new Task("Fix login", "high");
26        this.user = new User("Abidit", "developer");
27        this.active = false;
28    }
29
30    start() {
31        this.active = true;
32        return `Board active - ${this.user.describe()} assigned ${this.task.describe()}`;
33    }
34}
35
36const board = new TaskBoard();
37console.log(board.start());
```

Here, TaskBoard does not extend Task or User. It creates them in its constructor and uses them through their public methods. Each class stays small and testable on its own. If you need to change how tasks are described, you edit the Task class. If you need a different user format, you change the User class. The TaskBoard class just coordinates.
