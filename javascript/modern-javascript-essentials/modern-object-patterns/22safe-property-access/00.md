## Optional Chaining

Not every object will have every property you expect. The next two features let you read missing values safely.

When working with nested objects, accessing a property on something that is null or undefined throws a TypeError and crashes your program. Optional chaining (?.) solves this by short-circuiting to undefined instead of throwing an error when it encounters a missing link in the chain.

For example,

```javascript
1const player = {
2    name: "Abidit",
3    powerUp: {
4        type: "fireball",
5        duration: 10
6    }
7};
8
9console.log(player.powerUp.type);
10console.log(player.stats?.highScore);
```

Here, player.powerUp.type works normally because powerUp exists. That's simple and easy to understand.

But coming to highScore, player.stats?.highScore returns undefined safely, even though stats does not exist on player. Without the ?., player.stats.highScore would crash with a TypeError because you cannot access properties on undefined.

I use optional chaining any time I access a property more than one level deep and the intermediate object might not exist. For example, a user profile might or might not have a settings property, and settings might or might not have a theme. Using user.settings?.theme keeps your code safe without wrapping everything in if checks.

It's good if you reach for ?. whenever you work with data that could be incomplete, such as configuration objects, API responses, or optional game features.
