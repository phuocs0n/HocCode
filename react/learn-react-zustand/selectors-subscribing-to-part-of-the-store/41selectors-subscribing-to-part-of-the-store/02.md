## Derived State with Selectors

Sometimes you do not need the raw state. You need something computed from it.

Right now EntryList reads all entries and then filters them based on searchQuery. You could move that filtering logic into a selector instead.

In src/components/EntryList.jsx instead of two separate reads and a filter:

```react
const entries = useJournalStore((state) => state.entries)
const searchQuery = useJournalStore((state) => state.searchQuery)

const filteredEntries = searchQuery.trim() ? entries.filter(...) : entries
```

You can write one selector that does the work for you.

```react
const filteredEntries = useJournalStore((state) => {
  if (!state.searchQuery.trim()) return state.entries
  return state.entries.filter(
    (entry) =>
      entry.title.toLowerCase().includes(state.searchQuery.toLowerCase()) ||
      entry.content.toLowerCase().includes(state.searchQuery.toLowerCase()) ||
      entry.date.toLowerCase().includes(state.searchQuery.toLowerCase())
  )
})
```

One selector. The component does not need to know anything about how filtering works.
