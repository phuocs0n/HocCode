## Suspense Doesn't Fetch!

There's a distinction developers often miss:

```text
Suspense handles code loading, not data fetching.
```

The fallback we built here is triggered by a lazy component chunk downloading. It covers JavaScript loading, not API calls.

A first-time visitor to /entries/7 experiences two loading phases in sequence:

1. The JS chunk for EntryDetailPage downloads. <Suspense> shows the skeleton.
2. The chunk resolves, React renders the component, and then useEffect() fires to fetch data. Your component's own loading state shows Loading entry....

Both phases need to be handled:

- <Suspense> covers the first one automatically.
- Your component's loading state covers the second.

They are independent, and both matter. A page that handles only one of them will flash an empty or broken state during the other.
