## What Reducers in Context Actually Solve

The Misconception

A common assumption is that useContext() is for UI state (like themes) and useReducer() is for business logic, and that we would use one or the other, not both.

The idea of combining them feels redundant or overcomplicated.

The Truth

- useContext() solves where state can be accessed.
- useReducer() solves how state changes.

They address different problems, so combining them is natural.

Also remember this:

- Context makes the state global.
- The reducer makes the transitions explicit.

Together they give us a lightweight global state system built entirely from React's standard library, no third-party tools needed.

The Golden Rule

We put useReducer() inside a context provider when the state needs to be read or modified from multiple unrelated components, especially across route boundaries.

We keep the reducer function in its own file and export a useXxx() custom hook from the context file so consumers only need one import.
