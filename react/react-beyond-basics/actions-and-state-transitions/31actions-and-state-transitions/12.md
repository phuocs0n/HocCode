## What useReducer() Actually Solves

The Misconception

useReducer() is just a more complicated useState().

"I can do the same thing with setEntries(), why bother with all this extra boilerplate?"

The Truth

useReducer() isn't about being more powerful than useState(). It's about making state changes explicit and named.

When entries can change in two distinct ways, two separate useState() handlers make those changes invisible.

A reducer makes them a named, enumerated list. Every change to entries is a case in one place.

The Golden Rule

Reach for useReducer() when a piece of state can change in more than two distinct ways.

If you find yourself writing multiple handler functions that all call setState() on the same value, a reducer will make that logic clearer and easier to maintain.
