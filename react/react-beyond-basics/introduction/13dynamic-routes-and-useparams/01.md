## The Problem: Each Entry Needs Its Own URL

Recall that in the React Hooks course, we built a Drawer component. And clicking an EntryCard opens a side drawer showing the entry's full content.

It was a good solution for that stage of the app.

But it has the same URL problem we talked about in the previous lessons, and it's even more noticeable here.

Say you're reading entry 42 and you want to share it with someone. Unfortunately, you can't. The URL is still /.

There's nothing in the address bar that says "this specific entry." The person you send the link to will just see the journal list.

The browser's back button closes the drawer, but it doesn't feel right. You didn't navigate to a new page — you just opened a panel.

Users expect the back button to take them to the previous page, not toggle a UI element.

What we want is a unique URL per entry:

- /entries/1
- /entries/42
- /entries/99

Each one leads directly to that entry's detail screen. That's what dynamic routes give us.
