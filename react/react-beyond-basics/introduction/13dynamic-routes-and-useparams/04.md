## 💡Developer's Insight: Comparing IDs Safely

Never forget that useParams() always returns strings, but your API data might return IDs as numbers.

This means a strict equality check like entry.id === id will silently fail. For instance, 42 === "42" is false in JavaScript.

Here are two ways you can account for this problem and compare ids safely:

```react
// Convert the param to a number
entries.find(e => e.id === Number(id));

// Convert the entry ID to a string
entries.find(e => String(e.id) === id);
```

Pick one and stay consistent!

In this course, we use String(e.id) === id because it avoids NaN issues if the param ever contains non-numeric characters.

If the URL is /entries/abc:

- Number("abc") is NaN and every comparison fails silently.
- String(e.id) === "abc" just returns no match, which is easier to debug.
