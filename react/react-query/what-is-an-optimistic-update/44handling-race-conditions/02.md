## Chapter 4 Recap

Here's what you picked up in this chapter:

- An optimistic update changes the UI immediately before the server responds
- onMutate is where you snapshot the cache and apply the optimistic change
- onError is where you roll back using the snapshot if something goes wrong
- onSettled always runs last and syncs the cache with the server
- The full pattern is: snapshot in onMutate, rollback in onError, sync in onSettled
- cancelQueries in onMutate prevents race conditions from stale refetches
