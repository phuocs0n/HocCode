## The Fix is Already in the Pattern

The fix is actually already built into the optimistic update pattern we wrote. Remember this line in onMutate:

```react
await queryClient.cancelQueries({ queryKey: taskKeys.list({ status }) })
```

Every time a new mutation fires it cancels any in-flight queries for tasks. That means stale refetches can never overwrite our latest optimistic update.

And onSettled always does a final refetch after everything settles:

```react
onSettled: () => {
  queryClient.invalidateQueries({ queryKey: taskKeys.all })
}
```

No matter how many mutations fired or what order the responses came back in, after everything settles we go get fresh data from the server. The cache ends up correct every time.

So the full pattern is:

- onMutate: cancel queries, snapshot, update cache optimistically
- onError: roll back using the snapshot
- onSettled: invalidate and refetch to sync with the server

Follow this pattern every time you write an optimistic update and race conditions won't be a problem.
