## Rolling Back When Something Goes Wrong

If the server rejects the mutation, onError fires. We take context.previousTasks and put it straight back into the cache:

```react
onError: (error, updatedTask, context) => {
  queryClient.setQueryData(
    taskKeys.list({ status }),
    context.previousTasks
  )
},
```

The task status snaps back to what it was before. The user sees it change back and knows something went wrong.

Then onSettled runs no matter what, success or failure:

```react
onSettled: () => {
  queryClient.invalidateQueries({ queryKey: taskKeys.all })
},
```

This is the safety net. After everything settles we sync with the server so the cache always ends up in the correct state.
