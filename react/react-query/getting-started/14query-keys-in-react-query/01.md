## The Query Key Mistake Everyone Makes

Let's say you're building the filter feature in TaskFlow. The user picks a status and you fetch the matching tasks:

```react
const [status, setStatus] = useState('')
 
const { data: tasks } = useQuery({
  queryKey: ['tasks'],
  queryFn: () => fetchTasks({ status })
})
```

Spot the problem? You're using status inside queryFn but it's not in the queryKey.

So what happens? React Query fetches the open tasks and stores them under ['tasks']. The user switches to done. The status variable changes but the key is still ['tasks']. React Query finds data there and returns the old open tasks. It never goes to the server.

The fix is simple. Whatever you use inside queryFn must also live in queryKey:

```react
const { data: tasks } = useQuery({
  queryKey: ['tasks', { status }],
  queryFn: () => fetchTasks({ status })
})
```

Now when status changes, the key changes too. React Query sees something new and fetches fresh data automatically.

Good rule to keep in mind: if it affects what comes back, it belongs in the key.
