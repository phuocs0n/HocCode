## Chapter 2 Recap

Here's what you picked up in this chapter:

- useMutation is how you send changes to the server — creating, updating, or deleting
- Unlike useQuery, useMutation does nothing until you call .mutate()
- All API functions live in src/api.js, one function per job
- onSuccess runs automatically after a mutation succeeds — that's where you update the cache
- We use setQueryData to update the cache directly because DummyJSON doesn't persist changes

🔜 Next you'll learn how to design query keys that scale as your app grows, so your cache stays clean and your invalidations always hit the right data.
