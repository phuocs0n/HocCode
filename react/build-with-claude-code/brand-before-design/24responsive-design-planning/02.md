## Wireframes Before High Fidelity

For SpeedBlip, I never produced high-fidelity design files. The Framer output was good enough visually, but I used it as a wireframe reference - a layout guide, not a pixel-perfect spec.

This is a deliberate choice in rapid building. High-fidelity design files take time and create a false sense of completion. You can spend four hours making a beautiful Figma component and then spend eight hours trying to get Claude Code to match it exactly.

Wireframes give you what you actually need: the layout structure, the component hierarchy, and the content slots. When the brand guidelines are locked, the visual quality comes from the tokens - not from the fidelity of the wireframe.

The test for "is this wireframe good enough to code from?" is: can I describe this screen in plain English to someone who has not seen it, and would they build what I drew? If yes, the wireframe is done.
