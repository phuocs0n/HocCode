## Writing a Build Post

The SpeedBlip launch post followed a specific structure: it opened with a statement of what was built, showed the result before the process, connected the build to a real problem, and ended with a clear CTA.

The post structure that worked:

```react
[Hook - what you built in one line]

[The problem it solves - 1-2 sentences, personal and specific]

[What it does - 3-4 bullet points, concrete and jargon-free]

[What you learned - 1-2 sentences connecting the build to your expertise]

[CTA - one specific ask: try it, comment your speed, follow for more]
```

One thing I got right: the post was not about Claude Code. It was about the product - SpeedBlip. Claude Code was mentioned as a tool in passing, not as the subject. Posts that are primarily about AI tools perform worse than posts about real products that happen to have been built with AI.

The SpeedBlip post ended with: "Curious what speed you're getting right now - drop it in the comments." That comment prompt drove 40+ responses in the first two hours, which told the algorithm the post was generating conversation.
