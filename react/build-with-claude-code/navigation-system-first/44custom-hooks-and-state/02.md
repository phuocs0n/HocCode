## Timeout Fallbacks for Stuck States

Every async operation in SpeedBlip has a timeout. This was not in the initial design - it was added during the final fixes phase after the speed test was observed getting stuck in a loading state when Cloudflare's endpoint was slow to respond.

The fix in useSpeedTest:

```react
// 30-second timeout safety net
const timeoutId = setTimeout(() => {
  if (isRunning) {
    setIsRunning(false);
    setError('Speed test timed out. Check your connection and try again.');
  }
}, 30000);

// Clear timeout when result arrives
worker.onmessage = (event) => {
  clearTimeout(timeoutId);
  // handle result...
};

// Clear timeout AND terminate worker on unmount
return () => {
  clearTimeout(timeoutId);
  worker.terminate();
};
```

The cleanup return is not optional. Without this, a slow response from the Cloudflare API would leave the SpeedGauge spinning forever with no feedback to the user. The timeout creates a definite exit condition: after 30 seconds, the UI resets to a recoverable state with a clear error message.

It is good practice to add timeout fallbacks to every async operation that could get stuck. The cost is low (10 lines of code) and the protection against bad UX is high.
