## Each Chunk is Independently Testable

Here is the rule I used for every SpeedBlip chunk: when it finishes running, I should be able to open a browser and verify that what was built works correctly.

That means every chunk ends with a functional, deployable state. Not "partially built with the rest coming in the next chunk." Fully functional for its scope.

For example, Chunk 2a built only the navigation system. When it finished, I could:

- Navigate between routes in the browser
- See the sidebar collapse and expand on desktop
- Switch to a mobile viewport and see the bottom nav render
- Verify active states highlighted the current route

Only after all of that was confirmed did I commit the chunk and move to Chunk 2b. If any of those checks failed, I fixed it before moving on. The next chunk always starts from a working base.

It is good practice to write your test checklist for each chunk before you run the prompt. That way you are not making up what to verify after the fact - you know exactly what "done" means before you start.
