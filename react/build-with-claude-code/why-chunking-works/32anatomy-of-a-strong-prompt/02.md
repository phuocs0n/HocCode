## Behavior and Final Checks

The behavior section is where you describe what each piece of code should do in plain English, before Claude Code writes it. This is the most important section because it is where ambiguity causes the most problems.

For SpeedBlip's useSpeedTest hook, the behavior spec included:

```react
Reads interval setting from localStorage (default: 30 minutes)
Posts a "start" message to the Web Worker on mount
Listens for "result" messages from the Worker and appends to results array in state
Listens for "error" messages from the Worker and sets an error state
Exposes: { results, isRunning, error, runNow, clearHistory }
runNow() posts an immediate "start" message regardless of interval
Adds a 30-second timeout: if no "result" arrives, sets isRunning to false and sets error
Persists results to localStorage on every update
```

The final checks section closes the prompt with verification steps:

```react
After running: TypeScript should compile with zero errors. The Dashboard page should show a speed gauge and stat cards that update after running a test. Open browser DevTools and confirm the Web Worker is running in the Workers section. Check localStorage has a "speedblip-history" key after one test completes.
```

Writing final checks before running the prompt forces you to know what success looks like. It is remarkably easy to accept a partially-working output if you did not decide in advance what "done" means.
