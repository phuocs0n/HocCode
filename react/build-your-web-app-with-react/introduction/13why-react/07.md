## How React Compares to Plain JavaScript

When I first started learning React, I kept asking myself, "Why not just use plain JavaScript?" Here's what I've learned after building real projects with both:

Plain JavaScript is great when you start small.

You write 20 lines, add a click handler, and show a message. That's all! No setup, no new syntax.

But when you add more features, you're updating multiple parts of the page every time the data changes:

```react
// Update the header
document.getElementById("user-name").textContent = user.name;

// Update the count
document.getElementById("task-count").textContent = tasks.length;

// Rebuild the list
const taskList = document.getElementById("task-list");
taskList.innerHTML = "";
tasks.forEach(task => {
  const li = document.createElement("li");
  li.textContent = task.title;
  taskList.appendChild(li);
});
```

If you forget one spot, your entire UI is out of sync.

I've debugged this countless times myself. And trust me, each time it gave me a headache worse than the worst migraine I've ever suffered (figuratively speaking, of course).

React gets rid of this absurdity!

Instead of "when X happens, update Y," you say "here's what the UI should look like." and React updates the DOM for you.
