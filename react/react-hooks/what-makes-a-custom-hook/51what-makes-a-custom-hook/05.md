## 💡 Developer's Insight: The State That Kept Multiplying

Here's a case I ran into early on. Three screens in an app I was developing all fetched data from different endpoints.

Each had the same three state variables: data, isLoading, error. Each had the same useEffect() with the same try...catch block.

```react
// Copied into three different components...
const [data, setData] = useState(null);
const [isLoading, setIsLoading] = useState(true);
const [error, setError] = useState(null);

useEffect(function () {
  async function load() { ... }
  load();
}, [url]);
```

When the design team asked for a "retry" button on errors, I updated two components and forgot the third. Users on that third screen got a broken error state with no way to recover.

The fix was to extract the pattern into useFetch(). The result was a single place to update, and all three screens inherited the fix automatically.

```react
// In any component that needs data
const { data, isLoading, error } = useFetch(url);
```
