## Revisiting the Changes

Here's what changed from the previous lesson:

- App now has a refreshKey state (starts at 0). It lives in the useEffect() dependency array, replacing [].
- A Refresh button in the entry list header calls setRefreshKey() on click. React detects the change and re-runs the effect.
- The error display changed from a single <p className="error-state"> to an error-banner div with two child paragraphs.
- Header and EntryCard are unchanged from the previous lesson.

The Refresh button works because refreshKey is in the dependency array.

But what happens when a value the effect uses is not in the list?

That's the most common mistake when working with useEffect(), and I have a story from my early days that shows just how subtle it can get.
