#### Course: React Hooks: Level Up Your First Web App

## Two Problems, One Root Cause

1. The message is a lie when the list is genuinely empty.

If the API returns zero entries, the user sees Loading entries... forever. There's no way to tell if data is still coming or if the list is actually empty.

2. A failed request shows nothing.

If the fetch fails due to bad network, server down, wrong URL, etc., the following happens:

- entries state stays empty,
- loadEntries() silently swallows the error,
- and the user has no idea anything went wrong.

They just see Loading entries... and wait indefinitely.

Both problems have the same root cause: a single piece of state (entries) is being used to represent three different situations.

So, we need two more states:

1. One to track whether data is still loading.
2. Another to track whether something went wrong.

Let's add them one at a time.
