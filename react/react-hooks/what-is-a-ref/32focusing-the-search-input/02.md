## Focusing with useEffect() on Mount

Now, let's complete our modifications to Header.jsx.

We'll use useEffect() with an empty dependency array to run the code once, immediately after the component first appears on screen.

This is the right moment to focus the input — React has finished rendering, so the DOM element exists.

14        const res = await fetch("https://api.programiz.pro/api/Demo/v1/journal-entries");

21            ...post,

25          };
26        });
27        setEntries(mapped);
28        setIsLoading(false);
29      } catch (err) {
30        setError(err.message);
31        setIsLoading(false);
32      }
33    }
34    loadEntries();
35  }, [refreshKey]);
36

38    <div className="main-container">

44          <button
45            className="btn btn-secondary"
46            onClick={() => setRefreshKey((k) => k + 1)}
47          >
48            Refresh
49          </button>
50        </div>
51        {isLoading ? (
52          <p className="loading-state">Loading entries...</p>
53        ) : error ? (
54          <div className="error-banner">

63              key={entry.id}
64              id={entry.id}
65              title={entry.title}
66              date={entry.date}
67              content={entry.content}
68              author={entry.author}
69            />

Thanks to the empty array [], .focus() runs once on mount, and never again.

That's exactly what you want here: focus on load, not on every re-render.

But you might still wonder why we're using ref in the first place? Why not just use .focus() inside the effect directly? I can recount a personal incident about that, too.
