# Mobile-First CSS

#### Course: Make Your Code Work on Every Screen

## Mobile-First CSS

So far you've written desktop-first CSS. The base styles are for wide screens and max-width overrides them for narrow ones. That works, but it's the wrong way around.

Most people browse on their phones. So it makes more sense to write CSS for the smallest screen first and add layout as the screen gets wider. That way the worst case, limited space, is handled by default. Everything else is an enhancement.

Here's the same hero layout both ways.

Desktop-first.

```css
/* Works on desktop, breaks on mobile */
.hero-content {
  display: grid;
  grid-template-columns: 220px auto;
  gap: 64px;
}

/* On screens 48rem or narrower: collapse to one column */
@media (max-width: 48rem) {
  .hero-content {
    display: flex;
    flex-direction: column;
    gap: 1.5rem;
  }
}
```

Mobile-first.

```css
/* Base: single column, works on any screen */
.hero-content {
  display: flex;
  flex-direction: column;
  gap: 1.5rem;
}

/* At 48rem and up: two columns */
@media (min-width: 48rem) {
  .hero-content {
    display: grid;
    grid-template-columns: 14rem 1fr;
    gap: 4rem;
  }
}
```

The base styles are simple. The media query only adds complexity when there's room for it. The 48rem isn't a magic number, it's just where the hero needs two columns. You pick the breakpoint based on when your content needs more space.
