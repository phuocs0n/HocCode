## Analysis of O(n)O(\sqrt{n})O(n​) Complexity

Here's how the value k changed with respect to i in the last program.

| i | k |
| --- | --- |
| 1 | 1 |
| 2 | 1 + 1 |
| 3 | 2 + 2 |
| 4 | 2 + 2 + 3 |
| 5 | 2 + 2 + 3 + 4 |
| .
. | .
. |
| m | 2 + 2 + 3 + 4 + ….. + m - 1 |

The loop continues until k≥nk \geq nk≥n, based on the condition in the program.

Now, let's approximate the total value of k when the loop stops:

```text
k=2+2+3+4+…+(m−1)k = 2 + 2 + 3 + 4 + … + (m - 1)k=2+2+3+4+…+(m−1)
```

We approximate this to be roughly the sum of the first m natural numbers:

```text
⇒k≈m(m+1)2\Rightarrow k \approx \cfrac{m(m + 1)}{2}⇒k≈2m(m+1)​
```

Since the program stops when k≥nk \geq nk≥n, we say:

```text
m(m+1)2≥n\cfrac{m(m + 1)}{2} \geq n2m(m+1)​≥n
```

To simplify the math, we approximate again by treating this inequality as an equation and ignoring the +1 term and the division for large values of m:

```text
⇒m2≈n\Rightarrow m^2 \approx n⇒m2≈n⇒m≈n\Rightarrow m \approx \sqrt{n}⇒m≈n​
```

So, the loop runs for about n\sqrt{n}n​ iterations.

Hence, the time complexity of the program is:

```text
O(n)O(\sqrt{n})O(n​)
```

We used approximations twice — once to simplify the sum of terms, and once to convert an inequality into an equation — so the final time complexity is close to O(n)O(\sqrt{n})O(n​), not exact.
